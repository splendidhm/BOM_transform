# BOM 일괄 변환기

## 사용 순서

1. 압축 파일이라면 먼저 폴더 전체를 압축 해제합니다.
2. `실행.bat`을 더블클릭합니다.
3. 지정된 빈 양식과 저장 폴더를 확인합니다. 기본 양식은 동봉된 `templates/BOM 자동 입력 양식.xlsx`입니다.
4. 숫자로 된 RAW 엑셀 파일 여러 개 또는 폴더를 목록에 끌어 놓습니다. 파일 추가·폴더 추가 버튼도 사용할 수 있습니다.
5. **변환 시작**을 누릅니다. 목록 순서대로 처리하며 파일별 상태와 전체 진행률이 표시됩니다.
6. **저장 폴더 열기**로 결과를 확인합니다. 출력명은 `150149 완료.xlsx`와 같은 형식입니다.

폴더를 추가하면 하위 폴더도 탐색합니다. 숫자로 된 이름의 `.xls`·`.xlsx` 파일만 목록에 추가합니다.
같은 경로는 한 번만 추가합니다. 같은 제품코드가 여러 경로에 있으면 먼저 성공한 파일만 저장하고 나머지는 건너뜁니다.

## 저장과 오류 처리

- 기본 저장 위치는 프로그램 폴더의 `완료파일`입니다. 다른 폴더를 선택할 수 있습니다.
- 기존 완료 파일은 기본적으로 건너뜁니다. 교체하려면 **같은 이름의 완료 파일 덮어쓰기**를 선택합니다.
- 파일 하나가 실패해도 다음 파일을 계속 처리합니다. 오류 원인은 목록과 저장 폴더의 `변환기록` CSV에서 확인합니다.
- 대기 취소는 현재 파일의 처리를 마친 후 적용됩니다. 이미 저장된 파일은 유지됩니다.
- 각 파일은 임시 위치에서 생성·검증한 후 최종 이름으로 저장합니다. 검증에 실패하면 완료 파일로 저장하지 않습니다.
- 원본 RAW 및 양식 파일은 수정하지 않습니다.

## 적용 규칙

- A=RAW S 모품목코드, F=RAW W 자품목코드, G=RAW Z 단위, H=RAW AA 소요량.
- G는 EA·Meter·KG 등 원본 문자열을 그대로 사용하고 수량은 환산하지 않습니다.
- 단계 오름차순으로 정렬하며 같은 단계에서는 RAW 행 순서를 유지합니다.
- B=KG, C=M, D=0, E=1. I(Scrap)=해당 자품목의 직속 하위 구성품 행 수. J~T=공란.
- Scrap과 대체번호는 기존 테스트 규칙입니다. 실제 ERP 업로드용 확정 규칙은 아닙니다.
- 코드의 선행 0을 보존합니다. 원본 자체가 숫자로 저장해 잃어버린 선행 0은 복원하지 않습니다.
- 현재 지원: CP949/UTF-8 탭 구분 ERP 내보내기, 바이너리 XLS, XLSX의 첫 번째 시트. 헤더 및 단계 구조는 기존 RAW와 같아야 합니다.
- 양식의 32개 입력행보다 큰 BOM도 행을 확장하며, 추가 행은 첫 데이터 행의 서식을 따릅니다.
- 서로 다른 제품 파일의 반제품 BOM을 합치거나 중복 제거하지 않습니다. 파일별로 독립 변환합니다.

## 실행 환경과 구성

이 패키지는 **현재 PC의 Codex 번들 Python 3.12 및 Node/Artifact Tool 실행 환경을 사용하는 BAT 실행형**입니다.
Python·Node를 포함한 독립 실행 EXE는 아닙니다. 같은 실행 환경이 없는 다른 PC에 폴더만 복사하면 실행되지 않습니다.

필요한 기존 환경 위치: `%USERPROFILE%\.cache\codex-runtimes\codex-primary-runtime\dependencies`.
PyQt5와 xlrd는 `vendor`에 동봉되어 있으며 실행 중 다운로드하지 않습니다.
Qt는 [PyQt 공식 설치 안내](https://www.riverbankcomputing.com/software/pyqt/download)에 따른 PyQt5 wheel을 사용합니다.

- `app.py`: PyQt5 GUI와 순차 작업 스레드
- `bom_core.py`: RAW 읽기·매핑·양식 보존·저장 검증
- `artifact_engine.mjs`: Artifact Tool 엑셀 생성
- `templates`: 제공된 빈 양식
- `vendor`: PyQt5/Qt 및 XLS 읽기 라이브러리

프로그램 설정은 이 폴더의 `settings.json`에 저장됩니다. 파일이 없으면 기본값으로 시작합니다.
